# Purple Tokyo

A light/dark theme pair for [Super Productivity](https://github.com/super-productivity/super-productivity), plus a set of interface changes that go with it.

- **Dark — Shades of Purple (Super Dark):** deep indigo surfaces, white text, a muted violet for supporting text, Claude salmon as the accent.
- **Light — Tokyo Light:** cool blue-grey surfaces, ink-blue text, the violet of Shades of Purple as the accent, deepened so it carries on a light page.

Both palettes are taken from Personal Work Manager and remapped onto Super Productivity's [theming contract](https://github.com/super-productivity/super-productivity/blob/master/docs/theming-contract.md): the surface ladder and the ink primitives drive the semantic tokens, so most of the app follows from the two colour blocks at the top of the file. The rest covers the tokens the base pins to a neutral grey ramp that the ladder does not reach.

## Variants

Four further files pair the same interface changes with other palettes from Personal Work Manager. Everything below the two colour blocks is identical in all five, so a change to one section has to be repeated in the others; Super Productivity's installer accepts a single self-contained file and no `@import`, which is why the shared part is copied rather than referenced.

| File | Light slot | Dark slot |
| --- | --- | --- |
| `purple-tokyo.css` | Tokyo Light | Shades of Purple (Super Dark) |
| `paper-purple.css` | Licht — white and near-white zinc surfaces, Claude salmon accent | Shades of Purple (Super Dark) |
| `purple-tokyo-night.css` | Shades of Purple — indigo surfaces, white text, salmon accent | Tokyo Night — near-black blue surfaces, pale blue text, the theme's blue accent |
| `minimal-tokyo.css` | Tokyo Light | Tokyo Night — near-black blue surfaces, pale blue text |
| `shades-of-purple.css` | Shades of Purple — indigo surfaces, white text, salmon accent | Shades of Purple (Super Dark) |

`purple-tokyo-night.css` and `shades-of-purple.css` put a dark palette in the light slot, as asked. Shades of Purple is a dark theme in Personal Work Manager as well; it is the lighter of the two purples, not a light theme. Switching modes therefore moves between two dark looks rather than between light and dark, and Super Productivity still treats the light slot as light mode — its drop shadows and the platform's `color-scheme` for native widgets are the light-mode ones.

`minimal-tokyo.css` is the one file that names no accent. It leaves Super Productivity's primary palette alone, so the play button, the Add task button, links and every other primary-coloured control take the colour of the project or tag you are in and change with it — the approach the built-in `arc.css` takes, which sets an accent and never touches the primary.

## Install

Settings → General → Theme → **Install theme…**, then pick the `.css` file you want. It is stored locally in IndexedDB; nothing leaves the machine. Re-uploading a file with the same name overwrites the previous version. Installing more than one file puts all of them in the list.

The picker labels a theme after its filename, so rename the file if you want a different name in the list.

## What it changes beyond colour

Each section in the file stands on its own and can be deleted without touching the rest.

| Section | What it does |
| --- | --- |
| Typography | Inter throughout except the view title, which keeps the app's own stack; Inter is the face PWM uses (falling back to the app's own stack where Inter is not installed), JetBrains Mono for code. Includes an override for Material's components, which compile their own font family and never read the variable, and keeps the plugin security warning at normal body weight. |
| Side nav | The buttons in the Projects and Tags headers (add, add folder, visibility) and the two headings themselves stay out of sight until a pointer reaches either header block — a heading row or the buttons beside it — and then all of them come up together; keyboard focus does the same. Hovering a heading lights that whole block, buttons included, the way a nav row lights around its three-dot button. The Help entry is removed. Hover lights the whole row rather than the label alone. |
| Active My Day and Inbox | All three of `minimal-tokyo.css`, `paper-purple.css` and `shades-of-purple.css`. The icons on those two rows keep the colour they have when the row is not the open view, instead of being repainted with the active text colour. Labels and the row's own fill still mark which view is open, and an icon that carries a colour of its own is left alone. |
| Action bar | Every button except Play and Add task sits at 20% opacity, and each comes up on its own — the button under the pointer, or the one holding keyboard focus, and nothing else in the strip. That holds for the vertical rail; the horizontal row is governed by the top-bar autohide below. |
| Play and Add task | `minimal-tokyo.css` only, both modes. Neither takes the colour of the project, tag, My Day or Inbox: the disc under the play triangle and the ring that pulses on it are painted from `--play-button-bg`, the plus from body ink, and Add task answers the pointer with the same ink wash the dimmed buttons in the strip get. With nothing to track at all the play button is disabled, and there its disc and elevation go entirely and the triangle takes the colour those dimmed buttons come out at. |
| Flat surfaces | Task rows separate with a hairline instead of a drop shadow. |
| Page backdrop | Light mode loses the two primary-tinted glows the app paints behind the page; the flat page colour stands on its own. Dark mode keeps its wash. Super Productivity's own "Disable background tint" checkbox does the same thing, but it sits in each project's and tag's theme settings and covers both modes at once. |
| Disabled background tint | `minimal-tokyo.css` only. Where a project's or tag's "Disable background tint" box is ticked, the colours the app still fills from that context — the active row in the left menu, the date picker's hover fill, the info panels, the text selection — become body ink at the same weight, so the view holds no colour behind anything. Text, icons, outlines and the play button keep the context's colour. |
| Hairlines | `minimal-tokyo.css` only, dark mode. Separators and dividers are stated as a share of body ink mixed into the page (`--hairline-ink`, `--hairline-ink-soft`) rather than as PWM's own border colours, which sit high on near-black surfaces. |
| Fading rules | All three of `minimal-tokyo.css`, `paper-purple.css` and `shades-of-purple.css`, in both modes. A rule fades instead of stopping dead: a plain `<hr>` in a note or description comes in from the left and is gone by `--rule-fade` (`60%`) in from the right. In `paper-purple.css` and `shades-of-purple.css` the separator in the left menu fades at both ends too (`--menu-rule-fade-left` `8%`, `--menu-rule-fade-right` `20%`); `minimal-tokyo.css` drops that separator altogether, since the rail sets out its groups by spacing. The bar under a section heading — "Overdue" in the work view, the section headings in Settings — is gone everywhere in that theme, background image or not. The line under the Settings tabs stays flat and now runs the full width of the content view; it takes the theme hairline (`--separator`) in both modes, at `--settings-rule-weight` (`3px`). |
| Panel seams | `minimal-tokyo.css` only, every mode. The three full-height lines the side panels draw against the page — the rail's right edge, the right panel's left, and the one the vertical action bar draws against the content — are set to zero width; the columns are separated by surface colour instead. `--panel-seam-width` (`0px`) brings them all back at `1px`. All three files take the app's milk-glass treatment off the rail when a background image is active, so the rail keeps its theme surface either way. |
| Vertical rail | All three files. With the experimental vertical action bar on, the rail is narrowed by `--rail-inset` (`6px`), meets the strip behind the window controls in a rounded shoulder (`--rail-corner-radius`, `9px`) carrying a hairline (`--rail-corner-seam`, `1px`) that runs down the rail's left edge as its seam (`--rail-seam-color`, the hairline the left menu is seamed in, in both modes; transparent in `minimal-tokyo.css` in both modes, so that theme has no seam at all), starting 4px above the radius, just before the curve ends (`--rail-seam-offset`), at 30% strength (`--rail-joint-color`) and full over `--rail-seam-length` (`100px`; `200px` in light mode); the curve itself is clear for its first `--rail-curve-clear` (`19deg`, about 3px) and rises along the arc to that same 30% where it meets the rail — both `0` in `minimal-tokyo.css`; the strip itself rounds at `--strip-corner-radius`, `7px`), and the play button leans out over the rail's edge by `--play-button-overlap` (`6px`). |
| Top bar autohide | All three files, vertical rail off, from 600px up. Every control in the action row — Add task, sync, focus, counters, plugin and panel buttons — waits at `--action-bar-hidden-opacity` (`0`) until the pointer reaches the row or focus enters it; then all of them come back to the 20% idle dim, and the one under the pointer to full strength. Each control is one element, so they all fade the same way. The play button hides only when there is nothing it could start; ready or running, it stays put, and pointing at it does not lift the rest. Settings is left out. The fade is uneven on purpose: `--action-bar-fade-in` (`140ms`) with no delay, `--action-bar-fade-delay` (`300ms`) before `--action-bar-fade-out` (`500ms`). Settings → "Disable all animations" removes the fade, not the hiding. |
| Play at the end of the row | All three files, vertical rail off. The play button moves from the head of the action row to its far end, in the corner of the window; Add task stays where it was. The name of the running task, which that build draws beside the button, is anchored to its left; it fades whenever the pointer is anywhere in the header (pointing at the name itself counts, and brings the row up); only the play button proper keeps the name in view. The section is marked "PLAY AT THE END OF THE ROW" in the file. |
| Add to Today glass | All three files. With a background image the "Add to Today" button under an overdue list, and "Add more" under an empty one, become a frosted panel: the picture blurred hard beneath it (`--glass-blur`, `28px`), a tint over that (`--glass-tint`) — neutral in Minimal Tokyo, the theme's own deep purple in the two purple files, where Shades of Purple tints both slots, no rim, no shadow, and nothing on hover: the border is removed outright and the hover wash and ripple are switched off. |
| Material surfaces | Menus, dialogs, dropdowns, the date picker, cards and the snackbar take the theme's own surfaces instead of Material's grey. Tooltips stay deliberately contrasting. Segmented controls such as the dark-mode switch drop Material's grey for the theme's own surfaces. |
| Today icon | Replaces the sun with a bolt on the today affordances. My Day's row in the rail is not among them: the icon there is user data and a stylesheet cannot read what an element says, so the Lucide plugin maps the sun to a bolt by name instead. |
| Planner icon | Uses the built-in Material Symbols `next_week` glyph for Planner in the left navigation. |
| Schedule icons | Uses the built-in Material Symbols `calendar_clock` glyph for Schema in the left navigation and `pending_actions` on its right-panel button in desktop and mobile layouts. |
| Work view status bar | Puts one clock at the head of the "Resterende schatting / Vandaag werken / Zonder pauze" line by moving the icon the first reading already carries, drops the duplicate on the middle reading, and separates the three with a dot. The stopwatch on "Zonder pauze" stays. |
| Empty state | Hides the horizon drawing under "no tasks planned", adds `48px`-equivalent breathing room above the heading and keeps an explicit `32px`-equivalent gap before the add-more button. |
| Add task pop-up | The floating add-task bar opens further down the page instead of against the header. Desktop and mouse only: with touch the app pins the same bar above the keyboard and that is left alone. |
| Content scale | Keeps task lists, empty states and the finish-day action at their existing `1.1` scale while zooming the desktop Settings page out to `0.9`. |
| Right panel clearance | Starts the right panel below Electron's native window controls, which it otherwise opens underneath. It is on the panel rather than on what the panel holds, so it covers the task detail panel, project notes, an issue panel, the day schedule and a plugin view alike. The height is the same title-bar safe area the window-controls strip is drawn at, so the two cannot drift; `--detail-panel-top-gap` tunes it. |
| Dashboard icon | Gives plugin entries in the left menu the built-in Material Symbols `avg_pace` glyph in the same muted colour as Schema; no SVG asset is added. It reaches every plugin row, not only Dashboard: the app exposes no attribute saying which plugin a row belongs to, so there is nothing to narrow it with. |
| Project icon | Keeps a project's own colour on its icon in the left menu while that project is open. The app repaints the icon of an active row with the active text colour through an `!important` rule, which outranks the inline colour the icon carries, so the colour is read back from the palette the app writes on `html` for the open project. Project rows only — a tag stores its colour apart from its theme — and the rule stands aside on an app build that no longer overrides these icons. |
| Window controls | Places a compact theme surface behind Electron's native minimise, maximise and close buttons, matching the Windows reference while preserving native behaviour. Its dimensions follow Electron's native title-bar safe area, so Ctrl + scroll does not enlarge it. When the experimental vertical action bar is enabled, the rail starts directly below this surface and preserves the original Play position through internal top padding. In `minimal-tokyo.css` that surface takes the rail's own colour in dark mode (`--window-controls-bg`), as does the right panel, so the three edges of the window carry one surface. Below 600px — the width at which the app puts the left menu into its mobile shape — that surface drops out altogether, in all three files. `minimal-tokyo.css` also rounds the corner that notch leaves in the app (`--window-corner-radius`, `8px`), as VS Code and the system's own windows do; the section is marked "WINDOW CORNER" in the file. The buttons themselves are Electron's overlay, outside the page — a theme can paint the surface behind them and nothing else. |
| Square hover states | Squares the hover highlight on the left menu rows only. Everywhere else Material's own shape stands: icon buttons stay circular, and list and option rows keep their radius. The exception is the buttons in the Projects and Tags header rows: they take the same hover as the three-dot button on a nav row — a rectangle the size of the button, filled with the rail's hover tint — instead of Material's circle. |
| Tab selection | Marks the selected tab with a straight line instead of a shape. The Settings page rounds a tab's top corners and fills the selected one, which reads as half a rounded rectangle sitting on the header rule; the radius and the fill are dropped, the hover layer follows the tab, and the active indicator is squared at its ends. In `minimal-tokyo.css` that indicator also sits on the rule under the tab header rather than above it, at the same weight, so the selected tab colours a stretch of that rule instead of adding a second line beside it; in dark mode its label keeps the colour the other tabs carry, so the line is the only thing that marks it. |
| Inline task tags | Puts the project and tags on the task line instead of under it, separated by a hairline; long titles still wrap them to the next line. |
| Task text | Sets the task name as PWM does: Inter at 14px on a 20px line, regular weight, in the primary ink, and holds that weight and leading while the line is being edited. A finished name takes the muted ink through `--task-done-ink`, on top of the app's own strike-through and fade. |
| Task row controls | Play and the detail-panel toggle drop from 24px to 20px, and play takes the theme accent. |
| Plugin manager | Rebalances the plugin cards: a 26px icon, a 20.5px name, and descriptions, metadata and labels in muted ink at 15.5px with looser leading. |
| Compact menus | Brings the task context menu to 40px rows, a 12.5px label and 17px icons, tightens the tag, project and estimate submenus to 32px rows in regular weight, and squares the icon strip at its head with 23px glyphs. |
| Text rendering | Restores Windows subpixel rendering, which Material and the app switch off with `-webkit-font-smoothing: antialiased`. Icon faces keep greyscale smoothing. Bold type caps at SemiBold and inline emphasis at Medium, with table and section headers a step smaller. |
| Chrome scale | Puts the two navigation rails a step below the content in size. |

## Lucide icons

These themes draw the app's own icons by substitution: the ligature the icon font would have rendered is hidden and a different one is written in its place — a bolt where the sun was, and so on. That works because a Material icon is text.

If the [Lucide Icons plugin](https://github.com/roosmsg/super-productivity-lucide-icons) is installed, the whole interface is drawn in Lucide instead, and the substitutions above still hold: the plugin reads the ligature a theme has asked for and draws the Lucide equivalent, so the bolt arrives as Lucide's `zap` rather than as a Material glyph among Lucide ones. Nothing here needs changing for that to happen.

Two hooks are there for rules that should apply only when the plugin is drawing:

| Selector | Matches |
| --- | --- |
| `html[data-lucide-icons]` | anything, while the plugin is active — it removes the attribute when disabled |
| `mat-icon[data-lucide-icon="play_arrow"]` | one replaced icon, named by the Material ligature it stands in for |

The drawing itself lives in that element's `::after`, as a mask. A rule of your own that puts a mask there is left alone by the plugin, which is how a theme keeps an icon the plugin would otherwise replace.

## Tuning

- `--hairline-ink` (`6%`) and `--hairline-ink-soft` (`3%`) — `minimal-tokyo.css`, dark mode only: how much body ink is mixed into the page colour for the separator that edges cards, rows and panels, and for the quieter divider. PWM's own border colours (`#363b54`, `#232433`) sit high on surfaces this dark; these land at `#242632` and `#1f202c`. Lower either to fade the lines further, `0%` to remove them. The fading rules read the separator as well.
- `--panel-seam-width` (`0px`) — `minimal-tokyo.css` only: the width of the three lines the side panels draw against the page, the rail's right edge, the right panel's left and the vertical action bar's. `1px` is the width the app states and brings all three back at once; only the widths are set here, so each line keeps the colour its own component gives it. The section is marked "PANEL SEAMS" in the file and can be deleted whole.
- `--today-icon` — the Material Symbols ligature drawn in place of the sun. `bolt` by default; `electric_bolt`, `offline_bolt`, `flash_on` and `thunderstorm` are the other candidates in the app's icon picker. All five are carried by the Lucide plugin, so any of them still arrives as a bolt — Lucide's `zap`, or `cloud-lightning` for `thunderstorm` — rather than as a Material glyph among Lucide ones.
- `--icon-scale` — how large the Lucide plugin draws an icon, as a multiple of the size a glyph would have been. `0.92` by default; `1` is the app's own figure. It sits inside the plugin section and does nothing without it, since the icon font needs no such adjustment: a glyph is drawn at the element's font-size, while a mask fills whatever it is given, and the app states the two differently in places. Boxes do not move, so this shifts no layout.
- `--icon-scale-tasks` (`0.7`) — the same figure for the task list, the view around it and the detail panel, where the icons are controls sitting beside 14px text. The project and tag chips on a task line are exempt: a chip icon belongs to the label beside it rather than to the row's controls, and is read with it.
- `--break-reset-scale` (`0.75`), `--break-reset-opacity` (`0.55`) and `--break-reset-hover-ink` (the full ink) — the reset button on the "Zonder pauze" reading, which the app brings in at full size and full strength when that reading is hovered. It arrives smaller and part-transparent instead, and comes up to full strength and full ink when the pointer is on it. No hue: the change is one of weight, which is enough on the only thing moving, and keeps a reset button from announcing itself in the accent or in a warning red.
- `--planner-nav-icon` — the Material Symbols ligature used for Planner in the left navigation (`next_week`).
- `--schedule-nav-icon` and `--schedule-panel-icon` — the Material Symbols ligatures used for Schema in the left navigation (`calendar_clock`) and on the right-panel control (`pending_actions`).
- `--schedule-time-size` (`13px`), `--schedule-marker-size` (`12px`) and `--schedule-event-size` (`12.5px`) — the Schema grid: the hours down the side, the two work markers in the same gutter, and the tasks and appointments themselves. The app draws the first two at 11.2px and 10px, which is small for the labels everything else is read against, and the events at 14px, which is loud on a screen full of them. The labels come up and the events come down.
- `--schedule-header-date-size` (`15px`), `--schedule-header-title-size` (`17px`), `--schedule-header-btn-size` (`32px`) and `--schedule-header-btn-icon-size` (`19px`) — the bar above the Schema calendar: the day headers, the week with its date range, and the round controls for moving between periods and switching between day, week and month. All of it is chrome around a grid and the app draws it at full size. Sizes rather than a scale on the bar, so its height stays the app's and the grid below does not move.
- `--task-project-size` (`1.45em`) and `--task-project-icon-size` (`1.35em`) — the project on the task line, which reads as a heading for that line rather than as another chip on it, so it is set above the tags that follow. The icon is sized with the text, since one without the other leaves the icon looking like a leftover. Both are stated sizes, so the icon hands `--icon-scale` back to `1` and comes out the same in the icon-font build and with the Lucide plugin.
- `--detail-panel-icon-size` (`20px`) — the icons in the task detail panel, which stand beside short labels in a narrow column where the 24px the task list uses is more than the panel needs. Only the drawing steps down; the 24px box stays, so the rows keep their rhythm.
- `--work-view-scale` and `--settings-view-scale` — independent scales for the task work view (`1`) and desktop Settings page (`0.95`). Adjusting Settings does not change project pages. Both use `zoom`, which is a layout property, so the view really is smaller and lays out to the room it now has rather than being drawn smaller and clipped.
- `--add-task-bar-top` (`120px`) — the distance from the top of the window to the floating add-task pop-up. The app opens it at 48px plus a 20px margin, which sits against the header; the margin is cleared here, so this one number is the whole distance. Only in effect from the 600px breakpoint up and while a mouse is the primary input, since the touch layout puts the same bar at the bottom of the screen.
- `--play-button-hover-scale` (`1.06`) and `--play-button-hover-layer-opacity` (`0.12`) — the play button in the right action bar answers the pointer by growing slightly and deepening Material's own hover layer, whose default `0.04` is a figure meant for a large flat surface rather than a 46px circle. The growth is dropped for anyone who has asked the system for reduced motion, and neither applies while the button is disabled — which is how it sits when no task is selected.
- `--play-icon-ink` — the colour of the glyph inside the play button. Unset in Purple Tokyo, Purple Tokyo Night and Shades of Purple, where Material's own choice stands: the contrast ink the primary palette names for text on a filled button. Paper Purple sets it to white in light mode only, since that glyph is a 23px symbol on a 46px circle rather than a label, and white sits at 3.1:1 on the salmon — past the 3:1 a graphic that size needs; its dark half keeps the ink the app puts there. Minimal Tokyo points it at `--sidenav-text` in light mode, so the triangle takes the colour of the labels in the left menu, and in dark mode at the colour the dimmed buttons beside it come out at — the app's muted ink at the strip's idle opacity, flattened onto the chrome surface — since a glyph in those pale blue labels would light up the middle of the circle. In Minimal Tokyo the token covers the live button only: with no task to start, the glyph takes body ink — the colour the dimmed buttons in the strip come up to on hover, and what the Add task plus beside it does in that state. The other files paint the glyph in either state. Naming it here rather than changing `--palette-primary-contrast-500` keeps every other filled button as it was.
- `--side-nav-scale`, `--nav-footer-scale`, `--action-bar-scale` — the navigation scale in three places: the left rail (`1.05`), the search/timeline/settings group at the foot of that rail relative to the rail itself (`1`, matching the other rail buttons), and the right action strip (`0.85`). `--action-bar-idle-opacity` (`0.2`, `0.3` in light mode) dims every action-bar button except Play and Add task by 75% while the bar is idle, in both desktop layouts. `--play-button-size` (`46px`) sets the time-tracking button apart from the vertical strip scale; the strip widens to fit it. `--side-nav-icon-gap` (`15px`) is the space between a rail icon and its label; the app leaves 20px and this theme was collecting a further 12px from a rule written for context menus, which the rail matches because a nav link carries `mat-menu-item`. A plugin row keeps the app's own spacing: its icon is drawn differently and sits differently in the row.
- `--font-body-stack` and `--font-heading-stack` — the interface face. Both resolve to Inter, the face Personal Work Manager uses; install it (PWM carries `InterVariable.woff2`/`.ttf` under `src/renderer/public/fonts/`) or the stack falls back to Super Productivity's own default. Point `--font-heading-stack` at another family to set headings apart again.
- `--bold-font-weight` and `--emphasis-font-weight` — the caps applied to bold type (`600`) and to inline emphasis (`500`). Set both to `700` for the app's own weights.
- `--body-font-weight` — the interface weight (`400`). Raise to `500` if body copy still reads thin on this display; Inter carries a real Medium, so nothing is synthesised.
- `--window-controls-width` (`138px`) is the fallback width when Electron does not expose its native title-bar safe area; `--window-controls-bg` controls the backing strip's colour.
- `--vertical-action-bar-play-padding-top` (`12px` with the app's default spacing tokens) keeps Play separated from the native controls while the rail background starts at the top.

## Notes

- Themes installed through Settings cannot load external assets — no remote URLs, no `@import`, no bundled font files. The font stack therefore only names fonts that are installed on the machine.
- One selector keys off the Dutch button title `Voeg toe aan Mijn Day`, because that button carries no distinguishing class. With the interface in another language that line needs the string from that language.
- Setting the primary palette means per-project and per-tag colours no longer tint the interface. Delete the primary ladders and the accent block to hand that role back — which is what `minimal-tokyo.css` does: it names no accent of its own, so the play button, Add task, links and the rest of the primary-coloured interface take the colour of the project or tag you are in.
